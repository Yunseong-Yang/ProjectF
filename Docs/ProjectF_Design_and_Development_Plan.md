## 1. 문서 적용 원칙

이 문서는 이전 대화의 싱글플레이 전제를 PC 협동 멀티플레이로 대체한 통합 기준이다. 이전 초안과 충돌할 때는 이 문서의 협동·저장·스킬·테이크다운 규칙을 사용한다.

사용자가 직접 지정한 필수 요구사항:

1. 파크라이에서 영감을 받은 오픈월드 FPS의 정찰·잠입·교전·거점 공략 경험.
2. PC 멀티플레이에서 동료와 함께 적을 소탕할 수 있는 협동 플레이.
3. 협동 인원에 따른 적 체력·공격력 조정.
4. 실행 조건을 충족한 테이크다운은 적 체력과 협동 배율에 관계없이 확정 처형.
5. 다양한 테이크다운과 스킬 트리를 핵심 시스템으로 유지.
6. C++와 Blueprint 병행, 적 행동 결정은 StateTree 사용.
7. 신규 모델은 TripoSG, 모델 정리와 최적화는 Blender 사용.
8. 애니메이션은 Kimodo v1.2 및 Mixamo 활용.
9. 보유 Fab 라이브러리 활용. 모든 사용 모델과 Prop은 최적화 검사 필수.
10. Epic 공식 코딩 규약과 검증된 Unreal 프로젝트 관례 적용.
11. 에이전트는 크레딧·과금 자원을 소비하는 작업을 실행하지 않는다.

사용자의 권장안 채택 요청에 따라 아래 기본안을 선택한다. 플레이테스트 수치까지 영구 고정하는 것은 아니다.

| 구분 | 채택 기준 |
|---|---|
| 플레이 인원 | 1~4명, 혼자 또는 친구와 협동 PvE |
| 초기 세션 | 비공개 친구 방, Listen Server |
| 월드 소유 | 호스트 월드에 거점·보급망 진행 저장 |
| 개인 성장 | 플레이어별 스킬·장비 성장, 월드 진행과 분리 |
| PvP | 첫 버전 범위에 포함하지 않음 |
| 팀 이동 | 평상시 자유 분산, 강제 거리 제한 없음 |
| 아군 피해 | 첫 버전에서 직접 총격·폭발 피해 비활성 |
| 일시정지 | 협동 세션에서 개인 메뉴는 월드를 정지시키지 않음 |
| 아트 방향 | 현실적인 비례와 재질, 적·엄폐·장치의 가독성 우선 |
| 검증 목표 | 승인된 아트를 포함한 두 거점, 20~30분 플레이 |

표시 기준:

- **필수**: 제작과 검수에서 지켜야 하는 규칙.
- **초깃값**: 첫 플레이테스트를 위한 숫자. 결과를 기록하고 변경할 수 있음.
- **미검증**: 실제 실행·측정·계정 접근으로 확인하지 않은 사항.

문서화 과정에서 확인한 상태:

기존 템플릿은 사용 가능한 입력·이동·AI 패턴을 확인하는 참고 기반이다. 그대로 완성 게임의 구조로 간주하지 않는다. 기능을 새 구조로 옮기고 테스트한 뒤 기존 참조를 정리한다. Unreal 에셋은 파일 탐색기에서 일괄 이동하거나 이름을 바꾸지 않는다.

## 3. 게임의 핵심 경험

핵심 흐름:

**탐험 → 정찰 → 공격 순서와 진입로 선택 → 잠입·교란·교전 → 거점 확보 → 보급망 변화 → 장비·스킬 성장**

| 경험 | 설계 기준 |
|---|---|
| 발견 | 높은 곳·우회로·경보 장치·폭발물에서 유리한 선택을 발견 |
| 계획 | 지원 시설을 먼저 끊거나 주요 거점을 바로 공격할 수 있음 |
| 대응 | 잠입 실패 뒤 교전·도주·재진입이 이어짐 |
| 협동 | 정찰·엄호·침투·소생이 실질적인 기여로 인정됨 |
| 숙련 | 같은 장비로도 조준·위치 선정·테이크다운 연결이 향상됨 |
| 변화 | 점령 효과가 다음 전투와 이동에서 확인됨 |

잠입과 정면 교전은 모두 정상적인 공략이다. 발각을 임무 실패로 처리하지 않는다. 잠입 보너스가 있더라도 기본 완료 보상을 박탈하지 않는다. 동료 한 명의 실수로 전체 활동을 즉시 재시작하게 만들지 않는다.

### 3.1 콘텐츠 규모

첫 플레이 버전은 약 1㎢를 출발점으로 한다. 면적보다 활동 사이의 이동 시간과 공략 경로를 우선한다.

| 항목 | 첫 버전 | 이후 확장 방향 |
|---|---|---|
| 주요 거점 | 통신소 1, 주요 거점 1 | 세 지역, 지원·주요 거점 총 6개 |
| 안전 지점 | 1개 | 확보 거점에 기능 추가 |
| 탐험 지점 | 3개 | 지역별 정보·장비 보상 |
| 무기 | 소총부터 검증, 이후 권총·산탄총 | 지정사수소총 등 역할 확대 |
| 적 역할 | 일반병부터 검증, 경계병·중화기병 추가 | 전술 조합 확대 |
| 이동 | 도보 | 경량 차량 1종 |
| 시간·날씨 | 고정 주간 | 탐지·성능 검증 후 확장 |

항공기, 복잡한 야생동물 생태계, 전면 건물 파괴, 무제한 증원, 호스트 자동 이전, 공개 경쟁 매칭은 첫 버전에 포함하지 않는다.

## 4. 협동 세션과 플레이 흐름

### 4.1 방 생성과 참가

- 호스트가 자신의 월드를 선택하고 비공개 방을 연다.
- 초기 인원 상한은 호스트 포함 4명이다.
- 로컬 네트워크 테스트와 실제 인터넷 참가 검증을 별도 완료 항목으로 관리한다.
- 초대·검색·연결 제공자는 무료 이용 범위와 크레딧 차감 여부를 확인한 뒤 선정한다. LAN 접속 성공만으로 인터넷 협동 완성을 선언하지 않는다.
- 서로 다른 빌드·호환되지 않는 데이터 버전은 참가 전 거절하고 이유를 표시한다.
- 중간 참가자는 현재 월드 상태를 받은 뒤 안전한 위치에서 등장한다.
- 전투 중인 플레이어 바로 옆이나 적 시야 안으로 참가자를 생성하지 않는다.
- 자동 호스트 이전은 첫 버전에 없다. 호스트 종료 시 참가자에게 종료 사유와 보존된 진행을 안내한다.

### 4.2 자유 분산과 빠른 이동

- 일반 탐험 중 팀원이 서로 떨어져 움직일 수 있다.
- 한 명의 거리 이탈 때문에 다른 플레이어를 강제로 끌어당기지 않는다.
- 개인 빠른 이동은 자신이 교전·추적·수색 대상이 아니며 이동 목적지가 안전할 때 허용한다.
- 팀 전체 이동과 지역 전환은 준비 확인 후 실행한다. 다른 플레이어를 전투 중 강제로 이동시키지 않는다.
- 메뉴를 연 플레이어도 협동 월드에서는 공격받을 수 있음을 UI로 알린다.
- 실제 단독 세션에서는 일시정지를 지원할 수 있으나, 참가자가 있는 동안에는 로컬 메뉴가 월드를 멈추지 않는다.

### 4.3 협동 난도

| 해당 거점 참여 인원 | 적 체력 배율 | 적 공격력 배율 | 주둔병 초깃값 |
|---:|---:|---:|---:|
| 1 | 1.00 | 1.00 | 8 |
| 2 | 1.15 | 1.05 | 10 |
| 3 | 1.30 | 1.10 | 12 |
| 4 | 1.45 | 1.15 | 14 |

- 협동 보정과 쉬움·보통·어려움 보정을 분리한다.
- 거점 전투 개시 시 구역에 참여한 인원으로 기존 주둔병의 배율을 확정한다.
- 중간 참가·이탈로 현재 적의 최대 체력이나 남은 체력을 바꾸지 않는다.
- 다음 증원이나 다음 전투는 새 인원을 반영할 수 있다.
- 인원이 늘어도 화면 안에서 병력이 갑자기 생성되지 않는다.
- 서로 다른 거점을 공략하면 전투별 참여 인원을 사용한다.
- 예비 정찰·엄호 등 참여의 정의를 명시하고 단순 막타나 거리만으로 보상을 결정하지 않는다.

보정률뿐 아니라 처치에 필요한 탄수, 플레이어가 버티는 탄수, 탄약 소모, 소생 빈도를 측정한다.

## 5. 플레이어 조작과 상호작용

| 기능 | 초깃값·규칙 |
|---|---|
| 걷기 | 약 3.5m/s |
| 질주 | 약 6m/s, 사격 불가, 큰 발소리 |
| 앉기 | 약 1.8m/s, 소음·시인성 감소 |
| 조준 | 이동 속도 감소, 조준 감도 별도 |
| 점프 | 낮은 지형 통과 |
| 장애물 넘기 | 높이·진입·착지 공간이 유효한 낮은 장애물 |
| 질주 종료 | 약 0.25초 무기 준비 시간 |
| 스태미나 | 첫 버전에는 사용하지 않음 |

벽 달리기·자유 등반·포복·슬라이딩은 기본 이동 검증 후 별도 기능으로 판단한다.

상호작용 규칙:

1. 거리·시야·사용 가능 상태를 검사한다.
2. 화면 중앙과 가까운 유효 대상을 우선한다.
3. 대상 이름, 수행할 행동, 필요한 시간을 표시한다.
4. 일반 획득은 짧은 입력, 무기 교체·중요 시설 조작은 길게 누르기를 사용한다.
5. 이동·취소·사망·대상 소멸·거리 이탈의 처리 규칙을 갖는다.
6. 서버가 최종 유효성을 확인하고 중복 요청을 식별한다.
7. 두 사람이 동시에 같은 장치를 조작할 때 독점 여부와 결과를 명확히 한다.

## 6. 무기·사격·피해

### 6.1 휴대와 기본 무기

기본 휴대는 주무기 1개, 권총 1개, 투척 도구, 회복 도구다. 두 번째 주무기 슬롯은 성장 확장 후보로 둔다.

| 무기 | 기본 피해 | 탄창 | 발사 속도 | 재장전 | 주요 거리 |
|---|---:|---:|---:|---:|---|
| 권총 | 28 | 12 | 최대 300RPM | 약 1.6초 | 20m 이내 |
| 돌격소총 | 30 | 30 | 600RPM | 약 2.2초 | 15~60m |
| 산탄총 | 8발 × 14 | 6 | 80RPM | 발당 약 0.6초 | 10m 이내 |

예비 탄약 초깃값은 권총 48발, 소총 150발, 산탄 30발이다. 탄창 교체 시 남은 탄약은 버리지 않는다. 산탄총은 삽탄 완료된 탄부터 사용할 수 있다.

### 6.2 피해와 약점

일반 계산식은 `기본 피해 × 거리 × 부위 × 방호`다. 일반 적의 1인 기준 체력은 100, 권총·소총의 기본 머리 배율은 4배, 팔다리는 몸통보다 낮게 시작한다.

협동 체력 증가로 비장갑 일반병의 헤드샷 감각이 달라지는 것을 방지하기 위해 다음 약점 규칙을 채택한다.

- 권총·소총으로 유효 거리 안의 비장갑 일반병 머리를 정확히 맞히면 서버가 치명타 처치를 판정한다.
- 이 약점 처치도 적합한 무기·거리·노출 부위 조건을 서버가 검증한다.
- 헬멧 착용 적은 방호 파괴 규칙을 먼저 적용한다.
- 산탄총은 개별 산탄 한 개의 머리 명중만으로 치명타 처치하지 않고 누적 피해를 계산한다.
- 테이크다운은 별도의 확정 처형 규칙을 적용하며 헤드샷 규칙과 혼합하지 않는다.

### 6.3 조작과 네트워크

- 초기 소총·권총은 Hitscan을 사용한다.
- 카메라의 목표와 총구 앞 장애물을 모두 검사한다. 벽에 막힌 총구로 벽 너머를 사격할 수 없다.
- 서버는 무기 소유·탄약·발사 간격·상태·방향·요청 순서를 검증한다.
- 클라이언트가 주장한 피해량이나 피격 Actor를 그대로 확정하지 않는다.
- 반동과 발사음은 빠르게 반응하되 피해·탄약의 확정값은 서버 결과를 따른다.
- 발사 속도는 렌더링 FPS와 분리한다. 매 프레임 Reliable RPC를 보내지 않는다.
- 재장전은 시작·탄약 적용·완료·취소 시점을 갖는다. 요청 중복이나 몽타주 중단에도 탄약은 한 번만 변경한다.
- 첫 버전에서는 서버 판정 기반으로 시작하고, 지연 보상은 측정된 필요에 따라 범위와 최대 시간 창을 제한하여 추가한다.

무기 희귀도별 무작위 공격력은 첫 버전에 없다. 무기 종류, 부착물, 조작 숙련으로 차이를 만든다.

## 7. 체력·다운·소생·사망

플레이어 체력은 100, 보통 난도 일반 적의 소총 피해는 18에서 시작한다. 적은 거리·조준 시간·점사·엄폐·플레이어 이동을 반영한다. 모든 적이 동시에 완벽하게 명중하는 방식으로 난도를 만들지 않는다.

| 항목 | 초깃값·규칙 |
|---|---|
| 회복 도구 | 최대 3개, 사용 2.5초, 회복 60 |
| 회복 취소 | 효과와 소비 전에는 둘 다 취소, 적용 시점에는 둘 다 처리 |
| 자동 회복 | 전투 중 자동 체력 회복 없음 |
| 협동 다운 | 체력 0에서 다운, 약 30초 소생 기회 |
| 동료 소생 | 기본 기능, 약 5초, 피해·거리 이탈·시전자 다운 시 중단 |
| 소생 후 체력 | 40부터 시험 |
| 사망 후 재등장 | 약 15초 후 서버가 선정한 확보된 안전 지점 |
| 안전 스폰 불가 | 관전하며 안전 지점이 확보될 때까지 대기 |

일반 다운은 적별 처형 시스템과 다르다. 추락 등 복구 불가능한 사망 상황은 별도로 표시하고 안전 재등장으로 처리한다.

- 개인 사망은 다른 플레이어의 월드를 되돌리지 않는다.
- 첫 버전의 전원 전투 불능은 팀 안전 지점으로 재배치한다. 이미 확정한 거점·보상을 되감지 않는다.
- 미확보 거점은 플레이어가 멀리 있고 안전한 재편 조건을 만족할 때만 병력을 재편한다.
- 개인 사망·재등장으로 스킬과 영구 해금을 잃지 않는다.
- 사망만으로 예비 탄약·수류탄을 가득 채워 자원을 무한 생성하지 않는다. 복구용 최소 보급은 안전 지점 정책으로 별도 관리한다.
- 첫 버전의 아군 직접 피해는 비활성화한다. 동료의 투사체 차단·몸통 충돌·차량 충돌 정책은 테스트하며 일관된 방식으로 고정한다.

## 8. 정찰·잠입·정보 공유

정찰 도구로 적 역할·경보·진입로·환경 요소·지원 관계를 관찰한다. 약 0.7초 관찰 시 표식을 생성하는 값에서 시작한다.

- 직접 관찰 중에는 현재 위치를 표시한다.
- 시야에서 사라지면 마지막 목격 위치와 정보가 오래되었음을 표시한다.
- 벽 뒤의 실제 위치를 계속 갱신하지 않는다.
- 협동 표식은 팀에 공유하되 관찰하지 않은 정보를 새로 생성하지 않는다.
- 발견한 고정 시설·경보·지원 관계는 월드 지도에 기록한다.

| 소리 | 기본 감지 반경 초깃값 |
|---|---:|
| 앉아서 이동 | 3m |
| 걷기 | 8m |
| 질주 | 18m |
| 소음기 사격 | 20m |
| 일반 총격 | 100m |
| 큰 폭발 | 120m |

기본 시야는 정면 약 100도, 주간 탐지 거리는 약 50m에서 시험한다. 벽·지형·거리·노출·수풀·이동 상태를 반영한다. 이 숫자는 실제 음향이나 생리적 시야를 재현하는 수치가 아니다.

- 단단한 엄폐는 시야를 차단한다. 수풀은 탐지를 늦추지만 완전한 투명 상태를 부여하지 않는다.
- 소음기는 총성을 줄이지만 탄착음·피격·시체까지 숨기지 않는다.
- 한 명이 발각돼도 모든 적이 모든 팀원의 위치를 아는 상태가 되지 않는다.
- 감지와 기억은 대상별로 관리한다. 전달받은 보고도 위치·시간·출처를 갖는다.
- 통신소 차단은 외부 증원에 영향을 주며 가까운 적의 고함과 현장 대응은 유지된다.

## 9. 테이크다운 상세 규칙

### 9.1 반드시 유지할 원칙

**접근 조건과 필요한 스킬을 충족한 테이크다운은 적 체력·방어력·협동 체력 배율과 관계없이 확정 처형한다.**

공격력 9999 같은 일반 피해 편법으로 구현하지 않는다. 서버가 검증된 처형 결과를 별도 처리한다. 거점 난도 증가가 처형 성공 여부를 바꾸지 않는다.

### 9.2 종류와 해금

| 종류 | 조건 | 해금 |
|---|---|---|
| 기본 후방 | 비경계 일반 적의 후방, 거리·시야·공간 유효 | 시작 시 제공 |
| 공중 | 위쪽의 유효 낙하 경로와 착지 공간 | 잠입 트리 |
| 엄폐 | 지정한 모서리·엄폐 상황의 가까운 적 | 잠입 트리 |
| 연속 | 첫 처형 뒤 범위 안의 유효한 다음 적 | 잠입 트리 |
| 중화기병 | 해당 적 역할과 접근 조건 충족 | 중화기병 처형 스킬 |
| 처형 후 투척 연계 | 다음 적의 시야·거리·연계 자원 조건 충족 | 후반 잠입 트리 |

초기 후방 거리 1.5m, 적 뒤쪽 중심에서 좌우 각 60도를 시험값으로 둔다. 최종 범위는 캡슐·메시 크기·연출 위치에 맞춰 조정한다. 벽을 사이에 둔 처형은 허용하지 않는다.

### 9.3 서버 처리와 동시성

`요청 → 검증 → 대상 예약 → 위치 정렬 확인 → 처형 확정 → 연출 → 정리`

1. 요청 플레이어가 살아 있고 해당 행동을 사용할 수 있는지 확인한다.
2. 적 생존·역할·경계 상태·거리·방향·가림·스킬을 확인한다.
3. 대상 예약은 서버에서 원자적으로 처리한다. 같은 적에는 한 요청만 승인한다.
4. 실제 정렬 공간이 유효한지 검사한다. 확정 전 실패라면 예약과 입력 제한을 풀고 자원을 소비하지 않는다.
5. 처형 확정 시 적의 전투 기능을 즉시 중단하고 처치를 확정한다. 사망 연출은 끝까지 재생할 수 있다.
6. 서로 다른 적에 대한 동시 테이크다운은 허용한다.
7. 경험치·드롭·거점 병력 감소는 같은 처치 ID에 한 번만 적용한다.

| 예외 | 처리 |
|---|---|
| 같은 적에 동시 요청 | 첫 유효 예약만 승인, 나머지는 안내 후 정상 조작 복귀 |
| 요청 전에 다른 공격으로 적 사망 | 거절, 연계 자원 소비 없음 |
| 정렬 공간 막힘 | 확정 전 취소, 플레이어·적 잠금 해제 |
| 확정 후 공격자 다운·연결 종료 | 확정 처치는 유지, 연출·예약·입력 제한 정리 |
| 확정 후 다른 플레이어가 대상 사격 | 중복 처치·보상 없음 |
| 연속 처형의 다음 대상 무효 | 이전 처치는 유지하고 연속 행동만 종료 |
| 관련 구역 스트리밍 이탈 | 진행 중 행동을 유효하게 유지하거나 서버에서 종료 정리, 무한 예약 금지 |

테이크다운 중 공격자는 기본적으로 무적이 아니다. 공격자가 피해를 받아도 확정한 적 처치는 취소하지 않는다. 카메라·손·무기 연출은 본인용과 원격 관찰자용을 구분한다.

## 10. 스킬 트리·성장·경제

### 10.1 성장 구조

경험치로 레벨을 올리고 스킬 포인트를 획득한다. 기본 이동·정찰·후방 처형·동료 소생은 처음부터 제공한다. 장비 부착물은 설계도와 부품으로, 행동 해금은 스킬 포인트로 관리한다.

| 계열 | 1단계 예시 | 2단계 예시 | 3단계 예시 |
|---|---|---|---|
| 잠입·처형 | 공중 처형, 표식 유지 개선 | 엄폐 처형, 연속 처형 | 중화기병 처형, 처형 후 투척 연계 |
| 총기·전술 | 무기 전환 숙련 | 재장전 숙련, 반동 제어 | 투척 운용, 추가 장비 운용 |
| 생존·지원 | 회복 도구 휴대 | 회복 숙련, 신속 소생 | 보급 효율, 고급 지원 |

- 첫 트리는 계열당 4개, 총 12개 노드를 출발점으로 한다. 표의 모든 후보를 첫 버전에 넣겠다는 뜻은 아니다.
- 초기 노드는 1점, 고급 노드는 2점부터 시험한다. 세부 경험치 곡선은 실제 활동 시간을 측정해 정한다.
- 플레이어가 첫 거점 전후로 첫 선택을 경험하도록 조정한다.
- 개인의 해금은 다른 팀원에게 자동 적용되지 않는다.
- 협동 보너스가 중첩되면 합산·곱연산·최댓값 중 하나를 명시하고 상한을 둔다.
- 안전 거점에서 무료 스킬 재분배를 첫 버전 기본안으로 제공한다. 진행 중 행동과 교전 중에는 불가하다.
- 공격력 상승만 반복하지 않고 새로운 접근 방법·연계·편의를 제공한다.

### 10.2 자원과 보상

| 자원 | 용도 | 획득 |
|---|---|---|
| 부품 | 부착물·장비 업그레이드 | 거점, 탐험 |
| 보급품 | 회복·투척 도구 제작 | 보급 상자, 활동 |
| 경험치·스킬 포인트 | 개인 스킬 성장 | 전투·목표·협동 기여 |
| 탄약 | 사격 | 보급 지점·적·탐험 |

- 일반 보급 상자는 플레이어별 수령 기록을 가져 동료 한 명이 모두 소진시키지 않는다.
- 월드에 실제 놓인 무기·특수 물체는 단일 실체로 처리한다. 동시에 줍는 요청은 서버가 한 번만 승인한다.
- 첫 거점 보상과 설계도는 고유 보상 ID로 중복을 막는다. 반복 전투 경험치와 최초 완료 보상은 구분한다.
- 목표 참여·조사·엄호·소생도 기여로 인정하며 막타만 보상하지 않는다.
- 첫 버전에서는 플레이어 간 거래·아이템 던져주기를 제외해 중복·손실 경로를 줄인다.
- 기본 무기만으로 거점을 공략할 수 있어야 한다. 소모품 부재로 진행이 막히지 않는다.
- 전투 중 복잡한 제작 메뉴 사용을 요구하지 않는다.

## 11. StateTree AI

### 11.1 실행 위치와 역할

- StateTree 행동 결정·AI Perception·표적 기억·이동 요청·적 공격은 서버에서 실행한다.
- 클라이언트는 전달받은 이동·조준·행동 상태에 맞춰 표현한다.
- Animation Blueprint의 포즈 상태와 StateTree의 행동 결정을 구분한다.
- 일반병·경계병·중화기병은 공통 트리와 역할 데이터로 차이를 만든다.

```text
Root
├─ Dead
└─ Active
   ├─ Combat
   │  ├─ CallAlarm
   │  ├─ TakeCover
   │  ├─ FireBurst
   │  ├─ Reposition
   │  └─ Pursue
   ├─ Search
   │  ├─ MoveToLastKnownPosition
   │  ├─ SweepArea
   │  └─ ReturnToPost
   ├─ Investigate
   │  ├─ MoveToStimulus
   │  └─ Observe
   └─ Routine
      ├─ Patrol
      └─ Idle
```

| 사건 | 행동 |
|---|---|
| 사망·처형 확정 | 공격·이동·경보 취소, 최고 우선 종료 |
| 적대 대상 시각 확인 | Combat |
| 위치 불명의 소리 | Investigate |
| 교전 표적 시야 상실 | 마지막 목격 위치 추적·Search |
| 30~45초 수색 후 단서 없음 | 강화된 경계로 ReturnToPost |
| 경보 담당자 예약 성공 | CallAlarm |
| 장치 파괴·이동 실패 | 호출 예약 해제, 대체 행동 |

### 11.2 기억과 Task 규칙

대상별로 약한 Actor 참조, 마지막 목격 위치·시간, 소리 위치, 정보 출처, 유효 기간, 현재 시야 확보 여부를 기록한다. 시야가 없는 대상의 실시간 위치를 계속 참조하지 않는다.

- 변경되는 값은 Task Instance Data에 저장한다.
- Instance Data 타입을 명시적으로 등록한다.
- Condition은 판단만 하고 자원 소비나 상태 변경을 수행하지 않는다.
- Task는 성공·실패·취소·시간 초과를 갖는다.
- 이동 완료·몽타주 완료·감지 이벤트를 활용한다.
- 상태 종료·사망·UnPossess에서 타이머·델리게이트·발사 요청을 정리한다.
- 이전 요청의 늦은 결과가 새 상태에 적용되지 않도록 요청 ID를 확인한다.
- 전역 감지 작업 완료가 전투 상태 전체를 의도치 않게 끝내지 않도록 구성한다.
- 엄폐는 작성된 지점과 예약부터 시작한다. EQS 확장은 실제 필요가 확인될 때 적용한다.

## 12. 거점·경보·보급망

### 12.1 거점 구조

각 거점은 정찰 위치, 정문, 후방 통로, 고저차 접근, 경보, 핵심 조작 지점, 엄폐, 후퇴 공간, 증원 경로를 갖는다. 정문은 빠르지만 노출되고, 우회는 은밀하지만 이동·탈출 부담이 있게 만든다.

상태는 `미발견 → 발견 → 교전 중 → 확보`로 관리한다. 확보는 주둔병과 이미 도착한 증원병이 전투 불가이며 핵심 시설을 약 3초 조작했을 때 완료한다.

- 한 명의 유효 조작으로 팀의 거점 상태를 변경한다.
- 점령·보상·보급망 변경은 하나의 논리적 완료 작업으로 처리한다.
- 아직 도착하지 않은 증원은 점령 확정 시 취소한다.
- 마지막 적 탐색이 오래 걸리면 잔여 위협 구역을 안내한다.
- 확보한 거점은 첫 버전에서 자동 재점령하지 않는다.

### 12.2 경보와 증원

`위협 확인 → 호출자 예약 → 장치로 이동 → 4초 조작 → 호출 성공 → 외곽 진입`

- 장치 파괴·호출자 제압·조작 방해로 호출을 막을 수 있다.
- 호출자 사망·경로 실패·상태 취소 시 예약을 풀어 다른 적이 판단할 수 있게 한다.
- 첫 버전 증원은 일반병 4명, 거점 공략당 1회다.
- 통신 정상은 약 30초, 지원 통신소 차단 시 약 75초 후 도착을 목표로 한다.
- 서버 시간 기준 도착 예정 시각을 공유한다. 클라이언트마다 독립 타이머로 게임 결과를 결정하지 않는다.
- 실제 이동 경로를 포함해 도착을 검증하며 화면에 보이는 위치에 생성하지 않는다.
- 초기에는 도보, 차량 개발 후 차량 진입으로 확장한다.

### 12.3 지원 시설

| 시설 | 효과 |
|---|---|
| 통신소 | 연결된 거점의 증원 지연 |
| 탄약 보급소 | 아직 교전하지 않은 연결 거점의 중화기 배치 감소 |
| 차량 기지 | 연결 도로의 차량 순찰 감소 |
| 주요 거점 | 안전 이동·보급 지점 확보 |

지원 시설 없이 주요 거점을 공격할 수 있다. 이미 싸우는 적을 배치 감소 효과 때문에 삭제하지 않는다. 주요 거점을 먼저 확보해도 지원 시설의 독립 보상은 유지한다.

거점·지원 관계는 영구 ID로 연결한다. Actor 주소·화면 표시 이름을 저장 키로 사용하지 않는다. 구역이 언로드된 것을 사망·점령으로 해석하지 않는다.

## 13. 월드·탐험·차량

### 13.1 월드 구성

| 공간 | 목적 |
|---|---|
| 안전 지점 | 회복, 장비 변경, 제작, 저장, 빠른 이동 |
| 적 거점 | 정찰·잠입·전투의 집중 공간 |
| 탐험 지점 | 즉시 보급, 성장 재료, 공략 정보 |
| 연결 구간 | 순찰 회피, 지형 관찰, 경로 선택 |
| 정찰 지점 | 다음 목표와 시설 관계 파악 |

활동 사이 도보 이동은 대체로 1~3분을 목표로 한다. 길어지는 구간에는 경로 선택·위험·발견 중 의미 있는 요소를 둔다. 모든 지점을 전투로 채우지 않는다.

확장 지역의 역할은 해안의 근거리 교전, 산림의 정찰·우회, 산업 지구의 실내외 전환으로 구분한다. 스토리·인물·대사는 이 문서의 범위에 포함하지 않는다.

연기·조명·차량 이동·총성처럼 현장에서 발견할 수 있는 단서를 사용한다. 중요한 보상은 위치와 단서에 의미를 주고, 무작위 상자 밀도로 탐험을 대체하지 않는다.

### 13.2 스트리밍과 분산 플레이

- 거점·상호작용·보상 상태는 레벨 Actor가 없어도 논리적으로 보존한다.
- 여러 플레이어 주변의 활성 지역을 서버가 고려한다.
- 두 그룹이 분산되었을 때 서버 AI·메모리 예산은 한 거점만 측정한 값으로 승인하지 않는다.
- 가까운 위협을 성능 때문에 갑자기 삭제하거나 각 PC에 서로 다른 적을 생성하지 않는다.
- 먼 적의 업데이트 빈도를 줄일 때도 참여자 주변의 전투 결과는 유지한다.
- World Partition·Data Layer·HLOD 설정은 실제 지역 크기와 분산 시나리오로 검증한다.

### 13.3 차량 확장

도보 공략이 검증된 뒤 경량 오프로드 차량 1종을 추가한다. 도로 약 60km/h, 험지 약 35km/h를 시작값으로 한다. 연료·세부 정비·운전 중 사격은 첫 차량 버전에서 제외한다.

차량은 서버 소유의 좌석 예약·승하차·피해·저장 상태를 갖는다. 두 사람이 같은 좌석에 동시에 타거나 연결 종료 후 좌석이 잠기지 않게 한다. 물리 동기화, 충돌 피해, 안전 하차, 원격 애니메이션은 도보와 별도로 검증한다.

## 14. 저장·재접속·진행 소유

### 14.1 저장 경계

| 데이터 | 소유·보존 |
|---|---|
| 거점 확보·지원 시설·월드 발견 | 호스트 월드 |
| 플레이어 스킬·설계도·영구 성장 | 개인 프로필 |
| 현재 체력·탄약·장비·소비 도구 | 세션의 서버 확정 상태, 안전 시점 저장 |
| 그래픽·입력·접근성 설정 | 각 PC |
| 적의 순간 수색 경로·비행 중 탄환 | 첫 버전에서는 복원 대상 아님 |

게스트는 자신의 성장을 보존하지만, 다른 호스트의 거점 확보를 자신의 월드에 자동 복사하지 않는다. 첫 버전은 친구 협동과 로컬 프로필 보존을 전제로 한다. 프로필이 검증된 온라인 경쟁 경제라고 주장하지 않는다. 접속 후 변경은 서버가 관리하며, 첫 인증·프로필 식별 방식은 무료 연결 제공자 선정과 함께 검증한다.

### 14.2 저장 규칙

- 저장 형식 버전, 월드 ID, 플레이어 ID, 거점 ID, 고유 보상 ID를 사용한다.
- 거점 확보·보상·시설 효과는 하나의 완료 기록으로 적용한다.
- 임시 파일 작성과 최종 교체 등 손상 방지 방식을 사용하고 이전 정상 저장을 보존한다.
- 서버에서 확정하지 않은 로컬 예측값을 영구 저장하지 않는다.
- 개인 사망은 전체 저장 복원을 실행하지 않는다.
- 진행 중 처형·소생·재장전은 저장 가능한 안정 상태로 정리하거나 재개 시 취소 규칙을 적용한다.
- 저장된 순서와 다른 Actor 생성 순서에서도 ID 기반으로 복원한다.
- 구버전 저장은 지원 범위 내에서 변환하고, 지원하지 않으면 원본을 보존한 채 안내한다.

### 14.3 중간 참가·연결 종료

- 참가자는 월드 상태와 개인 상태 초기화 완료 후 조작을 시작한다.
- 일회성 연출 메시지만으로 현재 상태를 복원하지 않는다.
- 짧은 끊김 후 재접속은 동일한 플레이어 ID로 최근 서버 확정 상태를 복원한다.
- 연결 종료 시 처형·장치·좌석 예약과 입력 요청을 정리한다.
- 호스트의 정상 종료는 저장 완료 후 방을 닫는다.
- 호스트 강제 종료는 마지막 완료된 저장까지 보장한다. 이후 진행 손실 가능성을 명확히 표시한다.
- 첫 버전에서는 호스트 자동 이전과 클라우드 프로필 동기화를 제공하지 않는다.

## 15. UI·음향·접근성

### 15.1 화면과 지도

HUD에는 체력·탄약·선택 도구·상호작용·피해 방향·탐지 방향·현재 목표를 표시한다. 적의 체력 막대와 피해 숫자는 기본 비표시다. 방호 파손·피격·사망은 시각과 음향으로 구분한다.

협동 UI는 팀원 상태·다운·소생 진행·핑·네트워크 연결 상태를 제공한다. 팀원별 이름·색·기호를 함께 사용한다. 경보 호출 시도와 호출 성공을 구분한다.

지도는 미발견, 정보 부족, 정찰 완료, 확보 상태를 구분한다. 연결된 지원 시설과 확인된 효과를 보여주되 알지 못하는 정보는 미확인으로 표시한다.

소유권·동기화 실패가 게임 규칙과 혼동되지 않도록 다음 메시지를 구분한다: 대상 사용 중, 거리 이탈, 조건 미충족, 연결 지연, 서버 거절, 연결 종료.

### 15.2 입력·접근성

- 키 재설정, 일반·조준 감도 분리.
- 조준·앉기·질주의 누르기/전환 방식 선택.
- 시야각·카메라 흔들림·모션 블러 조절.
- UI·자막 크기 조절.
- 중요한 경고는 색만으로 구분하지 않음.
- 경보·탐지·소생에 시각·음향 피드백 동시 제공.
- 키보드·마우스를 먼저 검증하고 게임패드는 메뉴 탐색·입력 표시까지 함께 완료.
- 개인 메뉴가 협동 게임을 멈추지 않는다는 상태 표시.
- 테이크다운 카메라 움직임과 화면 흔들림 완화 설정.

### 15.3 시각·음향 기준

적 역할은 실루엣·장비로 구분한다. 시각적 엄폐와 실제 충돌·감지 판정을 일치시킨다. 역할이 같은 경보·조작 장치는 형태를 통일한다.

발사·재장전·방호 파손·탐지·경보·소생·처형의 주요 음향을 우선 제작한다. 여러 적의 같은 음성이 동시에 겹치지 않도록 제한한다. 음악은 긴장도를 보조하되 숨겨진 적의 정확한 정보를 유출하지 않는다.

환경 상호작용은 폭발성 용기와 파괴 가능한 경보 장치부터 구현한다. 넓은 화재 전파·건물 붕괴는 별도 비용·네트워크 검증 후 확장한다.

## 16. Fab·TripoSG·Blender 모델 제작 공정

### 16.1 소스 선정

| 대상 | 기본 경로 |
|---|---|
| 지형 재질·식생·바위 | 보유 Fab 후보 검사 |
| 건물·울타리·창고 모듈 | 보유 Fab 모듈 세트 검사 |
| 일반 소품 | Fab 재사용 또는 로컬 TripoSG |
| 고유 경보 장치·특수 시설 | 로컬 TripoSG → Blender 보정 |
| 캐릭터 | Fab 리그 캐릭터 우선 검토, 신규 제작 시 변형용 토폴로지·리깅 포함 |
| 무기 | Fab 후보 또는 신규 형상, Blender에서 총구·손잡이·탄창 구조 보정 |

모든 후보는 출처·이용 조건·형식·버전·실제 소유 여부를 기록한다. Fab에 로그인되거나 다운로드 파일이 있다는 사실만으로 모든 상품의 사용 가능성을 단정하지 않는다. 신규 구매, 크레딧 생성, 유료 변환은 금지한다.

### 16.2 공정

`원본 확보 → 검사 → Blender 정리·최적화 → 내보내기 → Unreal 가져오기 → 기능·품질·성능 검사 → 승인`

- TripoSG는 로컬 이미지 기반 형상 생성을 기본으로 사용한다.
- 생성 GLB는 출발점이다. UV·재질·충돌·리깅까지 완성되었다고 간주하지 않는다.
- 크기·방향·피벗을 고정하고 실제 내보내기/가져오기 왕복으로 단위를 확인한다.
- 중복 면·불필요한 내부 면·떠 있는 조각·노멀 오류를 검사한다. 의도된 열린 표면을 무조건 닫지 않는다.
- 실루엣과 기능 부위를 보존하며 리토폴로지·감면·노멀 베이크를 선택한다.
- 캐릭터는 관절 변형·웨이트를 보존한다. 일반 소품용 감면 비율을 캐릭터에 일괄 적용하지 않는다.
- 문·창·총열·탄창·손잡이 등 기능 부위는 별도 검사한다.
- 원본·작업본·내보내기 결과를 분리한다. 원본을 파괴적으로 덮어쓰지 않는다.
- 로컬 환경이 실패하면 Blender 수작업·기존 에셋·단순 블록아웃으로 진행한다. 유료 웹 생성으로 전환하지 않는다.

| 가까이 보이는 무기 | 20,000~60,000 | 2~4 | 2K 중심 |
| 적 캐릭터 | 30,000~60,000 | 2~4 | 2K 중심 |

식생·건축·대형 지형·Nanite·1인칭 팔은 별도 프로파일을 둔다. 반복 배치 수와 화면 점유율을 함께 기록한다. 예산 초과는 측정 근거와 기록된 예외가 없으면 승인하지 않는다.

필수 검사:

- 실제 수입 후 정점 수, 삼각형, 재질 분할, 텍스처 크기.
- 용도에 맞는 LOD·Nanite와 원거리 표현.
- 단순 충돌 우선, 동적 물체에 불필요한 복잡 충돌 제외.
- 반복 물체의 인스턴싱 가능성.
- 식생의 겹치는 투명 영역·그림자·바람 변형 비용.
- 공통 재질·재질 인스턴스 재사용.
- 근접·원거리·음영·충돌·애니메이션 시각 검사.
- 단일 에셋뿐 아니라 대표 밀도 배치 장면 측정.

Nanite를 켜거나 삼각형만 줄였다는 이유로 최적화 완료를 선언하지 않는다. 이미 기준을 만족하는 Fab 에셋은 검사 결과를 남기고 유지할 수 있다.

### 16.4 승인 기록

각 모델은 출처, 작업 도구 버전, 원본·결과 식별값, 용도, 형상·재질·충돌 통계, 비교 이미지, 대표 배치 조건, 판정을 기록한다.

상태는 `작업 중 / 수정 필요 / 승인`으로 관리한다. 메시·재질·텍스처·충돌·LOD가 바뀌면 관련 승인을 다시 받는다. 미승인 모델은 테스트 맵에서만 사용하고 출시 대상 맵의 의존성 검사에서 차단한다.

## 17. Kimodo v1.2·Mixamo 애니메이션 공정

### 17.1 역할과 로컬 경로

- Kimodo-SOMA-RP-v1.2: 로컬 동작 생성, 프롬프트·제약·버전·시드 보존.

- Blender: 스켈레톤 변환·루트·접지·관절·무기 접촉 보정.
- Unreal: IK Rig·Retargeter, AnimBP, Montage, 게임 상태 연결.

Kimodo 기본 NPZ를 곧바로 Unreal용 FBX로 취급하지 않는다. `NPZ → 로컬 변환 → Blender Action → 검증된 FBX 내보내기 → Unreal` 경로를 샘플로 먼저 검증한다. 변환에 필요한 스켈레톤 정의·기준 자세·단위·프레임레이트를 고정하고 자동 변환 성공을 가정하지 않는다.

### 17.2 리그와 이동

- 적 전신은 프로젝트 표준 휴머노이드 스켈레톤을 중심으로 통합한다.
- 기본 후보는 UE 마네킹 계열 호환 구조이며 실제 Fab 후보의 변형·애니메이션 호환성을 보고 선택한다.
- 원본 Kimodo·Mixamo 리그는 보존하고 파생본으로 변환한다.
- 1인칭 팔은 별도 표시용 메시·애니메이션을 허용한다.
- 루트와 골반, 발 접지, 전방 축, 기준 자세, 소켓 이름을 고정한다.
- 일반 이동은 In-place + Character Movement로 시작한다.
- 정밀 상호작용은 필요한 동작에 한해 Root Motion·정렬 보정을 적용하고 네트워크 이동 충돌을 검사한다.

- 행동 ID·시작 시각·단계로 원격 동작을 맞추고 전체 뼈 Transform을 계속 전송하지 않는다.
- 애니메이션이 누락되거나 중단돼도 이동·공격·입력이 영구 잠기지 않는다.
- 원격 캐릭터와 근접 팔의 애니메이션 비용을 각각 측정한다.

### 18.3 코드 관례

- Epic 공식 C++ 규약 우선, UE 5.8.4 실제 헤더와 시그니처 확인.
- 타입별 A/U/F/E/I 접두사와 프로젝트 PF 접두사, PascalCase, bool의 b 접두사.
- 예: APFWeapon, UPFHealthComponent, FPFWeaponState, EPFAlertState, bIsReloading.
- 헤더·구현 분리, 필요한 헤더 직접 포함, `.generated.h`는 마지막 include.
- 외부 모듈 공개 선언에는 API 매크로 적용.
- 소유 UObject 참조에 적절한 UPROPERTY와 TObjectPtr, 비소유 대상은 Weak Reference 검토.
- 대형 선택적 에셋은 Soft Reference와 명시적 로딩 사용.
- Tick은 실제 필요와 빈도를 설명할 수 있어야 함.
- 종료·취소 시 타이머·델리게이트·요청 정리.
- 검증 실패와 개발 불변 조건을 구분하고 유효하지 않은 콘텐츠를 무조건 강제 종료하지 않음.
- 공개 함수에는 필요한 계약·제약을 기록. 주석으로 코드 동작만 반복하지 않음.
- 수치와 에셋 경로를 코드 여러 곳에 분산 하드코딩하지 않음.
- 코딩 규칙을 맞추기 위한 무관한 대규모 리네임·포맷 변경은 별도 작업으로 분리.

## 19. 네트워크 구현 기준

- 서버가 피해·탄약·처형·아이템·스킬·거점·보상·저장을 확정한다.
- 로컬 이동은 Character Movement의 예측·보정 경로를 활용한다. 임의 위치 순간이동으로 예측을 대체하지 않는다.
- 소유한 PlayerController·Pawn·컴포넌트를 통해 요청한다. 소유하지 않은 거점 Actor에 직접 Server RPC를 호출하는 구조를 피한다.
- 요청 데이터의 소유권·범위·시간·횟수·현재 상태를 검증한다.
- 지속 상태는 복제 속성·스냅샷으로 전달한다. Multicast만으로 점령·사망·스킬 해금을 저장하지 않는다.
- OnRep와 상태 적용은 반복 호출에 안전해야 한다. 같은 결과로 보상을 재지급하지 않는다.
- 비공개 인벤토리·상세 성장 정보는 필요한 소유자에게만 보낸다.
- 고빈도 장식 효과와 지속 게임 상태의 전달 방식을 구분한다.
- 휴면·거리 관련성으로 전송량을 관리하되 다시 관련성이 생겼을 때 현재 상태를 복원한다.
- 첫 연결·재접속·중간 참가·리스폰·맵 전환을 각각 검증한다.
- 첫 기반은 기본 Actor Replication으로 구현하고 Push Model·Iris·Replication Graph는 실제 병목과 버전 제약을 확인한 뒤 선택한다.
- Listen Server의 로컬 플레이어와 원격 참가자 모두 같은 게임 검증 규칙을 적용한다.

## 20. 단계별 개발 계획

이 문서는 전체 게임의 즉시 자동 실행 지시가 아니다. 구현을 요청받은 단계와 범위만 수행한다. 비용 정책에 걸리는 단계는 무료·로컬 대안으로 바꾸고 불가능한 부분을 기록한다. 다른 가능한 작업은 계속한다.

| 단계 | 선행 | 산출물 | 완료 조건 |
|---|---|---|---|
| M0 기준·목록 | 없음 | 버전·원본 기준점·Fab 목록·비용 확인 | 소유와 실행 경로를 확인, 원본 복구 가능 |
| M1 제작 공정 샘플 | M0 | 소품·캐릭터·동작 샘플과 검수 | 로컬 생성·변환·최적화·수입 경로 재현 |
| M2 협동 기반 | M0 | 프로젝트 클래스·접속·스폰·테스트 맵 | 호스트+클라이언트 이동, 4인 접속·퇴장 |

## 21. 성능·메모리·네트워크 검증

### 21.1 임시 예산

아래 예산은 목표 PC 선정 전의 제안값이다. 현재 성능 합격이나 최소 사양이 아니다.

| 항목 | 초깃값 |
|---|---|
| 클라이언트 | 1920×1080, 중간 품질, 60FPS |
| 프레임 시간 | p95 ≤16.7ms, p99 ≤25ms 목표 |
| 프로세스 RAM | 최대 8GiB 목표 |
| GPU 메모리 | 최대 5GiB 목표 |
| 서버 갱신 | 30Hz부터 시험, 서버 프레임 p95 ≤33.3ms 목표 |
| 단일 전투 | 4인 + 주둔 14 + 증원 4 등 실제 배치 |
| 분산 전투 | 2+2명이 두 거점에서 동시에 싸우는 실제 규모 |
| 네트워크 시험 | RTT 약 0/80/150ms, 손실 0/1/3%, 실제 인터넷 별도 |

서버 갱신 목표와 각 Actor의 전송 빈도, 클라이언트 FPS는 별개다. Listen Server는 렌더링과 서버 작업이 같은 PC에서 수행되는 비용도 측정한다. 대역폭 예산은 M2~M3에서 실제 전송량을 얻어 정한다. 아직 없는 값을 0으로 기록하지 않는다.

### 21.2 세 가지 성능 판정

1. **프레임·작업량:** 평균, p95/p99, Game/Render/GPU 비용, 최초 로딩·반복 진입 지연.
2. **메모리:** 정상·최대 RAM/VRAM, 반복 생성·제거·재접속·저장 후 증가와 정리.
3. **CPU/GPU 배치:** AI·권한 게임 규칙·저장은 CPU, 렌더링 병렬 작업은 GPU 등 실제 비용과 이유를 확인. GPU 사용 자체를 합격 조건으로 삼지 않음.

같은 맵·카메라·해상도·품질·병력·빌드·캐시 조건에서 전후를 비교한다. Editor의 작은 장면만으로 패키지 게임을 인증하지 않는다. 필수 적을 줄이거나 품질을 낮춘 결과를 같은 조건의 최적화 성공으로 보고하지 않는다.

현재 판정: 기능·아트·성능 모두 이 문서 작업에서는 **미구현 또는 미검증**. 실제 증거가 없으면 PASS로 바꾸지 않는다.

## 22. 자동 검증과 필수 시나리오

Unreal Data Validation을 확장해 검사 규칙을 작성한다. 내장 기능 활성화만으로 다음 항목이 모두 검사되거나 패키징이 자동 차단되는 것은 아니다. 검증 실행과 실패 시 빌드 중단을 별도로 연결한다.

자동 검사 후보:

- 거점 ID·보상 ID 중복.

- 모델 승인 기록과 최신 결과의 일치.
- 재질·텍스처·충돌·LOD 프로파일.

- 출시 맵에서 테스트·미승인·불필요한 원본에 대한 의존성.
